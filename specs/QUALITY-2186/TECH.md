# Restore local child owners after cloud-parent VM handoff

## Summary
On [QUALITY-2186](https://linear.app/warpdotdev/issue/QUALITY-2186/restore-local-child-owners-after-cloud-parent-vm-idle-destroyhandoff), a resumed cloud parent can display its former children but cannot receive mail on behalf of its local children. Recreate each native/Oz local child's lightweight owner inside the resumed parent's environment. Subscribe to the child's own run events immediately, but fetch its full transcript only when a message or pane open requires it. Do not implement the runtime change in this spec PR.

## Proposed changes
1. **List before the parent can execute.** Add a headless cloud-parent restoration step after the parent conversation exists and before its first resumed turn, including `--skip-initial-turn` completion. Page `GET /agent/runs?ancestor_run_id=<parent>&limit=100` until `page_info.has_next_page=false`; pass each `next_cursor`, reject a missing or repeated cursor, and deduplicate results by run ID. Keep the existing `Vec<AmbientAgentTask>` API for unrelated callers; introduce a page-returning client method whose result carries `runs`, `page_info.has_next_page`, and `page_info.next_cursor`. Reuse this method for the GUI ancestor seed so that GUI restoration also sees results after page one. Do not silently skip an undecodable child row in the restoration path; fail that page. Do not fetch child transcripts in this step. On a failed or incomplete list, retry the existing transient-fetch policy before releasing the parent; fail closed with a reported parent setup error rather than running with an unknown child set. The parent cannot send to a child until this step completes.
2. **Classify and materialize.** List the direct children twice with the same parent filter: the full result for existing remote viewer behavior and `execution_location=LOCAL` for the persisted-worker-backed local set. Membership in the local-filter result is authoritative even when the response field says `REMOTE`. Limit owner creation to local tasks with native/Oz harness metadata; retain remote children as passive placeholders. Do not classify by `source` or an active execution's worker accessor. For each local result, reuse the server conversation token, existing run ID, parent conversation ID, title, harness, and workdir from the parent environment. Use the existing hidden child pane and `ChildAgent` entry path to own a **lightweight** conversation with no fabricated transcript or new server task. Index the owner by child run ID; a repeated seed, SSE reconnect, or repeated parent restoration must not create a second owner, pane, or consumer. A local child without a usable server conversation token cannot resume: mark that child Error through the same failure path as a transcript load failure.
3. **Separate wake from delivery.** Track each owner's state as `Unhydrated → Hydrating → Ready | Error`. Register each lightweight child as a consumer of its *own* `RunIds([child_run_id])` SSE. Seed its cursor from the child's durable acknowledged sequence at discovery, or zero when none exists; do not merge a newer server cursor during wake. While its state is `Unhydrated` or `Hydrating`, listen for a new-message event as a wake trigger only. Do not fetch or enqueue its message body, persist/ack an advanced event cursor, mark any message delivered, or let the controller start an LLM turn. Do not replace the child's own stream with the parent's ancestor stream. On wake, stop the wake-only listener and initiate hydration. On a pane open, initiate the same hydration operation even without mail. Coalesce concurrent wake and pane-open requests into one operation keyed by child run ID.
4. **Hydrate before running.** Fetch the *existing* conversation token with `get_ai_conversation`, convert with `RestorationMode::Continue` using the lightweight owner's existing `AIConversationId` rather than a new default ID, and merge the transcript and server metadata into that owner. Preserve the child run ID, parent link, child role, and child-owned terminal surface. Only after successful installation may the normal child SSE restart from its unchanged durable cursor, fetch and enqueue the pending message, and release the controller's readiness gate. An already-interrupted child turn is not resumed from an in-memory stream; the persisted transcript is authoritative, and the next delivered message starts the next turn. The parent may send after metadata restoration; only **child** injection waits for full hydration.
5. **Fail closed and report.** On any transcript fetch, decode, conversion, or installation failure, stop that child's wake listener, keep its normal drain gate closed, and transition both the local conversation and server task to `Error` with a diagnostic identifying the child run and failed stage. Use the existing `AIClient::update_agent_task`/status reporting path or the smallest explicit equivalent if local status sync cannot report an Error without a turn. Do not execute a child request or confirm a message; do not retry the failed child automatically. If reporting Error to the server fails, surface that failure instead of claiming success. A later deliberate restoration may retry only after re-establishing a new owner from durable state.

### Ownership and lifecycle contracts
- One local child owner belongs to the resumed **parent process**, not to a new child VM or a remote viewer. The restored parent environment already contains the child's working files. `AgentDriver` must not create a second independent workspace or server run for it.
- The handoff lifecycle destroys the old parent VM **before** the new parent revives children. This is an explicit precondition, not a concurrency case to solve here. Do not add cross-VM generation fencing. Check this ordering in the VM A→B validation; if it is false, stop this design for a new safety review.
- Only a running parent sending to its direct native/Oz local child is in scope. No initial undelivered-inbox scan or periodic poll. Do not use present `read_at` timing as a reason to add reconciliation; its read point is being fixed separately.

## Decisions
- **Eager owner metadata, lazy transcript:** eager full transcript loads simplify the first message but scale with child history and slow parent handoff. Metadata-only owners establish the inbox subscription before the parent resumes; one transcript loads on first use.
- **Persisted worker filter over response/source:** `execution_location=LOCAL` query membership is backed by persisted worker ID. The task's `source` describes how it started; the response's derived location can misclassify ended local runs. Two lists preserve remote viewer behavior without relying on either field.
- **Wake-only over normal pre-hydration SSE:** normal draining can advance the durable cursor and dispatch a `Success` stub before restoration. Wake-only consumes no body and does not advance the cursor; normal replay starts after full restoration. This is distinct from the existing dormant-Claude wake bridge, which stays unchanged.
- **Error over blank continuation/retry:** running without a transcript can corrupt the child context. Stop execution and report Error instead of generating a new conversation or silently retrying.
- **Lifecycle precondition over generation fencing:** the requester confirms the old VM cannot be alive when the child revives. No second concurrently active owner exists under this contract.

## Assumptions
- A resumable native local child has a server conversation token and its transcript can be loaded from the server. A missing token or transcript is an Error, not a reason to start a fresh child.
- Existing parent environment restoration finishes before child owner creation. Child-specific workspace reconstruction is unnecessary.
- A failed ancestor listing must prevent parent execution because it is not safe to infer that undiscovered children are remote. Child transcript failures affect only that child after discovery succeeds.

## Out of scope
- Remote child execution or viewer redesign; non-Oz local child harnesses, including the Claude wake bridge.
- Messages sent while the parent VM is absent, or child-to-parent/external-to-child delivery. No undelivered-inbox scan, polling, or change to `read_at` semantics.
- Overlapping parent VMs or new cross-VM ownership fencing; revisit the design if the destruction-before-revival precondition changes.
- Desktop startup/transcript laziness ([APP-5876](https://linear.app/warpdotdev/issue/APP-5876)), server schema changes, and child snapshot/VM creation.

## Testing and validation
These checks apply to a later implementation, not to this spec-only PR. Add tests in adjacent `*_tests.rs` files for [`restoration.rs`](https://github.com/warpdotdev/warp/blob/1e1acb4d74b3f55155860a785152bd23a2f3d83b/app/src/pane_group/child_agent/restoration.rs), [`orchestration_event_streamer.rs`](https://github.com/warpdotdev/warp/blob/1e1acb4d74b3f55155860a785152bd23a2f3d83b/app/src/ai/blocklist/orchestration_event_streamer.rs), and [`driver.rs`](https://github.com/warpdotdev/warp/blob/1e1acb4d74b3f55155860a785152bd23a2f3d83b/app/src/ai/agent_sdk/driver.rs). Run all named cases with `cargo nextest run -p warp --lib -E 'test(restored_local_child_)'`; run `cargo check -p warp` and `cargo clippy -p warp --all-targets --tests -- -D warnings`.
- **VM A→B:** `restored_local_child_vm_a_to_b` uses two process lifetimes in the test fixture: destroy A, restore the parent and child in B, then send parent→child mail. Assert the child's run ID, server conversation token, parent link, and working directory remain stable; assert B retains the same local conversation ID from its lightweight owner through hydration. Assert one owner and own-run SSE exist before parent send, zero early transcript fetches, and one message turn. Record A termination before B owner creation.
- **Pagination and idempotence:** `restored_local_child_pagination_and_idempotence` feeds 101 direct children across pages, including a repeated run ID. Assert one owner and SSE per unique local child. Fail on a repeated/missing cursor; retry a transient list failure before the parent turn. An incomplete listing must not release the parent.
- **Remote and non-Oz:** `restored_local_child_classification` mixes native local and remote tasks, an ended native local result whose response says `REMOTE`, and a non-Oz local child. Assert only native persisted-local members become owners; remote/non-Oz children acquire no new native owner or own-run SSE.
- **Wake and races:** `restored_local_child_hydration_gate` delays transcript fetch while two SSE wake events and pane open arrive. Assert one fetch, unchanged durable cursor and delivery status, zero child requests before hydration, then one normal replay and one LLM turn. Re-seed and reconnect without duplicates.
- **Transcript failure:** `restored_local_child_transcript_error` makes fetch, decode, and conversion fail in separate cases. Assert local and server Error, no child request or delivery confirmation, and continued ownership of other children. Simulate failed Error reporting and assert the reporting failure is visible.
- **Lifecycle precondition:** `restored_local_child_vm_a_to_b` asserts A termination before B creates an owner. A contrary production orchestration trace blocks deployment pending a new design review; overlapping-owner behavior is not in this scope.
