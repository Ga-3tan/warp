# Restore local child owners after cloud-parent VM handoff

## Summary
On [QUALITY-2186](https://linear.app/warpdotdev/issue/QUALITY-2186/restore-local-child-owners-after-cloud-parent-vm-idle-destroyhandoff), a resumed cloud parent can display its former children but cannot receive mail on behalf of its local children. Recreate each native/Oz local child's lightweight owner inside the resumed parent's environment. Subscribe to the child's own run events immediately, but fetch its full transcript only when a message or pane open requires it. Do not implement the runtime change in this spec PR.

## Proposed changes
1. **Correct the public API contract first.** In `warp-server/router/handlers/public_api/run_execution_location.go:41-45`, derive the existing response `execution_location` from persisted `run.Task.WorkerID`, not the active execution. `local` means `LOCAL`; every other value, including an unset worker, means `REMOTE`. Keep the `LOCAL` filter bound to `ai_tasks.worker_id=local`; change the `REMOTE` filter to `worker_id IS DISTINCT FROM 'local'` so SQL `NULL` and nonlocal values match the response. Do not infer ownership from `source`. Review `warp-server/router/handlers/public_api/agent_webhooks.go:2672-2722`: the corrected label alone must **not** grant a terminal run `session_id` or `session_link`. Retain the pre-change active-local-execution predicate for that local-link exemption, with existing retained-session and GCS-transcript rules unchanged; an ended local task without a live execution must not gain a potentially stale link to its destroyed host. This corrects labels without making a stale session joinable. Update the public contract description to say the location is the persisted run-worker classification, not proof of a currently live execution. Deploy the corrected server before enabling one-pass ownership discovery in clients. The old server returns valid but wrong `REMOTE` values, so a client cannot detect compatibility from this field; use a client-side rollout flag that remains disabled until deployment is confirmed in that environment. When the flag is enabled, reject a child whose response omits `execution_location`; do not classify it as remote.
2. **Share one complete direct-child traversal.** Introduce a strict page-returning `AIClient` method in `warp/app/src/server/server_api/ai.rs:1002-1028,1404,2664-2675` that exposes `runs`, `page_info.has_next_page`, and `page_info.next_cursor`. Keep the current lenient `Vec<AmbientAgentTask>` method for unrelated callers. Implement one reusable asynchronous `discover_direct_children(ai_client, parent_task_id)` helper used by **all three** seeds below. Request an unfiltered `ancestor_run_id`, `sort_by=created_at`, `sort_order=asc`, and up to 100 rows per page. Continue until `has_next_page=false`. Reject a missing, empty, or repeated `next_cursor` while more pages remain. Fail the whole traversal on an undecodable row, a missing `execution_location`, or a child whose `parent_run_id` is not the requested parent; ignore an accidental parent row. Deduplicate by run ID in first-seen order; conflicting parent, location, or harness data for one ID fails the traversal rather than choosing an owner arbitrarily. Return a complete traversal or an error, not partial results. It is **not an atomic snapshot**: rows can change or arrive between pages. Do not create a global seed cache or combine role lifecycles.
3. **Gate the headless parent and classify once.** After the resumed cloud parent's conversation and environment exist, await the shared traversal before its first resumed turn or `--skip-initial-turn` completion. On a transient failure, retry before releasing the parent; on a nontransient or persistently incomplete traversal, report a parent setup error and do not start the turn. Use each row's corrected `execution_location` to classify `LOCAL` versus `REMOTE`. Only native/Oz local children become owners; non-Oz local and remote children remain passive observations. Treat an absent harness as Oz, matching the server's default (`app/src/ai/agent_sdk/mod.rs:1858-1873`); an unknown or explicitly non-Oz harness never becomes a native owner. For each owner, reuse the server conversation token, existing run ID, parent conversation ID, title, harness, and workdir from the parent environment. Have `TerminalDriver::create` retain the handle of its already-created `PaneGroup`, and expose it to the parent `AgentDriver`; resolve the parent pane by terminal-view ID with `PaneGroup::find_pane_id_for_terminal_view` (`app/src/pane_group/mod.rs:2216-2229`). In that group's `ViewContext`, make an owner-side metadata-only child `AIConversation` indexed by the existing run ID and bound to the existing token; restore it into a hidden child terminal pane with `PaneGroup::create_hidden_child_agent_pane`. Give the child its own controller/terminal surface and own-run event consumer; never reuse the parent's controller or consumer. Track run ID → child conversation/pane in the parent driver and reconcile with the history run-ID index; repeated seeds, SSE reconnects, and repeated parent restoration must not create a second owner, pane, or consumer. Do not fetch a transcript, create a server task, launch a new VM, or create a second workspace. A hidden child terminal shell within the existing workspace is allowed. If a passive placeholder for the same child run was created in this process before owner restoration, replace or promote it without losing the run-ID mapping; do not let a placeholder suppress owner creation. A local child without a usable server conversation token enters the Error failure path.
4. **Reuse traversal in GUI and Observer, not their lifecycle.** `PaneGroup::spawn_ancestor_list_fetch_if_needed` (`app/src/pane_group/child_agent/restoration.rs:180-229`) calls the shared helper. Keep its pending-parent map, in-flight dispatch token, task-resolution retries, five-second transient retry, terminal-surface check, and hidden-pane reconciliation. Preserve existing hidden panes for children that a **locally owned** GUI parent already owns. For a cloud-owned parent viewed in the GUI, treat every server-discovered child, including one labeled `LOCAL`, as a passive placeholder; its owner lives in the cloud-parent process, not in the viewing desktop. Never create a new child owner from a server-discovered row merely because it says `LOCAL`. In the headless parent's own workspace, defer passive GUI seeding until the headless owner pass finishes, and then let the existing run-ID mapping preserve each local owner while adding remote placeholders. `OrchestrationEventStreamer::spawn_ancestor_seed_fetch` (`app/src/ai/blocklist/orchestration_event_streamer.rs:1325-1407`) calls the same helper. It seeds `known_children` as **passive** viewer pills for all child locations, without creating owners or reading child inboxes. Keep the refcounted viewer registry. Do not mark the viewer seeded or open its `AncestorRunId { include_self: false }` SSE until the entire traversal succeeds. On failure keep its existing next-registration/reconnect retry policy; do not accept a partial page. Guard completion with a generation token so a request from a removed viewer registry cannot seed a new registry for the same parent.
5. **Protect Observer cursor handoff.** The server's `last_event_sequence` is an acknowledged per-run cursor, not a pagination snapshot barrier. Do not advance the viewer SSE cursor to the maximum child sequence returned across pages: a new child can be missed or move between pages while that cursor advances. Start the ancestor SSE from the viewer's locally persisted, already-processed cursor captured before traversal, and deduplicate replayed child IDs against `known_children`. Persist the cursor only for events the Observer processes; never push it to the server. This can replay more historical lifecycle events than the former max-child shortcut, but avoids discarding child creation during traversal. An event for a child absent from the traversal must still create its passive pill after SSE starts. The headless parent remains gated until its traversal succeeds; no traversal alone guarantees an atomic view of concurrent external child creation.
6. **Separate wake from delivery.** Track each owner's state as `Unhydrated → Hydrating → Ready | Error`. Register each lightweight child as a consumer of its *own* `RunIds([child_run_id])` SSE. Seed its cursor from the child's durable acknowledged sequence at discovery, or zero when none exists; do not merge a newer server cursor during wake. In particular, bypass the existing `spawn_task_harness_fetch_if_needed`/`finish_restore_fetch` max-with-server cursor path (`app/src/ai/blocklist/orchestration_event_streamer.rs:1648-1695,1901-2045`) for unhydrated children. While its state is `Unhydrated` or `Hydrating`, listen for a new-message event as a wake trigger only. Do not fetch or enqueue its message body, persist/ack an advanced event cursor, mark any message delivered, or let the controller start an LLM turn. Do not replace the child's own stream with the parent's ancestor stream. On wake, stop the wake-only listener and initiate hydration. On a pane open, initiate the same hydration operation even without mail. Coalesce concurrent wake and pane-open requests into one operation keyed by child run ID.
7. **Hydrate before running.** Fetch the *existing* conversation token with `get_ai_conversation`, convert with `RestorationMode::Continue` using the lightweight owner's existing `AIConversationId` rather than a new default ID, and merge the transcript and server metadata into that owner. Preserve the child run ID, parent link, child role, and child-owned terminal surface. Only after successful installation may the normal child SSE restart from its unchanged durable cursor, fetch and enqueue the pending message, and release the controller's readiness gate. An already-interrupted child turn is not resumed from an in-memory stream; the persisted transcript is authoritative, and the next delivered message starts the next turn. The parent may send after metadata restoration; only **child** injection waits for full hydration.
8. **Fail closed and report.** On any transcript fetch, decode, conversion, or installation failure, stop that child's wake listener, keep its normal drain gate closed, and transition both the local conversation and server task to `Error` with a diagnostic identifying the child run and failed stage. Use the existing `AIClient::update_agent_task`/status reporting path or the smallest explicit equivalent if local status sync cannot report an Error without a turn. Do not execute a child request or confirm a message; do not retry the failed child automatically. If reporting Error to the server fails, surface that failure instead of claiming success. A later deliberate restoration may retry only after re-establishing a new owner from durable state.

### Ownership and lifecycle contracts
- One local child owner belongs to the resumed **parent process**, not to a new child VM or a remote viewer. The restored parent environment already contains the child's working files. `AgentDriver` must not create a second independent workspace or server run for it.
- The handoff lifecycle destroys the old parent VM **before** the new parent revives children. This is an explicit precondition, not a concurrency case to solve here. Do not add cross-VM generation fencing. Check this ordering in the VM A→B validation; if it is false, stop this design for a new safety review.
- Only a running parent sending to its direct native/Oz local child is in scope. No initial undelivered-inbox scan or periodic poll. Do not use present `read_at` timing as a reason to add reconciliation; its read point is being fixed separately.

## Decisions
- **Eager owner metadata, lazy transcript:** eager full transcript loads simplify the first message but scale with child history and slow parent handoff. Metadata-only owners establish the inbox subscription before the parent resumes; one transcript loads on first use.
- **Correct existing field over adding another:** deriving public `execution_location` from persisted task worker aligns the response with the existing LOCAL filter, including ended children. A new ownership field would preserve the current field's accidental semantics but add schema and client rollout work. One unfiltered list now discovers both local owners and remote viewers. This changes web location/environment labels, cloud-platform display and timeline selection (`warp-server/client/packages/agents/src/pages/Runs/util.tsx:32-64`, `run-platform.ts:132-151`, `RunDetailPane.tsx:622-627`; Factory equivalents), desktop conversation-card icon classification (`app/src/ai/agent_conversations_model/entry.rs:175-185`, `app/src/ui_components/agent_icon.rs:102-110`), and CLI JSON output. Server session links must be decoupled from the corrected label to avoid claiming a destroyed local host remains joinable.
- **One traversal over one global seed:** sharing page decoding, cursor validation, ordering, and deduplication removes three diverging 100-row caps. Headless owners block parent execution; GUI seeds reconcile panes; Observer seed opens read-only SSE. A shared singleton seed would conflate readiness, retry, and cursor policies across separate processes and viewer permissions. Do not build one.
- **Existing hidden pane over a second headless terminal factory:** `TerminalDriver::create` already creates a `PaneGroup` in the headless process. Reusing its hidden child pane yields the separate terminal/controller needed for child commands without another workspace. Building a standalone headless terminal factory would duplicate the pane group's owner setup and require a new terminal lifecycle. Only the seed's initiator, readiness gate, and metadata-stub hydration differ from GUI restoration.
- **Observer replay over max-child cursor:** starting from the viewer's persisted processed cursor can replay old events. Advancing to the maximum child `last_event_sequence` during a non-atomic multi-page traversal can skip concurrently created children. Prefer replay and deduplication.
- **Wake-only over normal pre-hydration SSE:** normal draining can advance the durable cursor and dispatch a `Success` stub before restoration. Wake-only consumes no body and does not advance the cursor; normal replay starts after full restoration. This is distinct from the existing dormant-Claude wake bridge, which stays unchanged.
- **Error over blank continuation/retry:** running without a transcript can corrupt the child context. Stop execution and report Error instead of generating a new conversation or silently retrying.
- **Lifecycle precondition over generation fencing:** the requester confirms the old VM cannot be alive when the child revives. No second concurrently active owner exists under this contract.

## Assumptions
- A resumable native local child has a server conversation token and its transcript can be loaded from the server. A missing token or transcript is an Error, not a reason to start a fresh child.
- Existing parent environment restoration finishes before child owner creation. Child-specific workspace reconstruction is unnecessary.
- A failed or malformed ancestor listing must prevent parent execution because it is not safe to infer that undiscovered children are remote. Child transcript failures affect only that child after discovery succeeds.
- The server-first rollout gate is an explicit deployment precondition; a syntactically valid `REMOTE` result from an older server is not evidence of remote ownership. This rollout decision is not discoverable from the existing wire field. Disable the new client restoration path where corrected server deployment is unconfirmed; a missing location after activation fails the traversal.

## Out of scope
- Remote child execution or viewer redesign; non-Oz local child harnesses, including the Claude wake bridge.
- Messages sent while the parent VM is absent, or child-to-parent/external-to-child delivery. No undelivered-inbox scan, polling, or change to `read_at` semantics.
- Overlapping parent VMs or new cross-VM ownership fencing; revisit the design if the destruction-before-revival precondition changes.
- Desktop startup/transcript laziness ([APP-5876](https://linear.app/warpdotdev/issue/APP-5876)), a new public field or database schema change, and child snapshot/VM creation. Correcting the existing public response/filter and client strict page decoder **is in scope**.
